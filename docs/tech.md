# Tech stack

## Engine / runtime

- **Engine:** Phaser 3 (latest 3.x on npm at the time of writing: 3.90.0). Exact version gets pinned at scaffold time in phase 2.
- **Language(s):** TypeScript (strict)
- **Target platforms:** Web browser, desktop and mobile landscape. LAN only via `vite --host`, never deployed publicly.

## Libraries / frameworks

| Library | Version | Purpose |
|---------|---------|---------|
| phaser | 3.x (pin at scaffold) | Rendering, scenes, input, tweens, cameras |
| vite | pin at scaffold (latest seen: 8.3.5) | Dev server (`--host` for phones on home wifi), build |
| typescript | pin at scaffold | Types; `src/contracts.ts` is the shared contract |
| @playwright/test | pin at scaffold | QA: gameplay tests, frame-time measurement at 60 and 120 Hz |
| JSON schema validator (TBD in phase 2) | — | Validate every `data/*.json` at boot |

## Tooling

- **Package manager:** npm
- **Build:** Vite, scaffolded with the official Phaser or Vite scaffolder (decided in phase 2, per make-game scaffold rules)
- **Testing:** Playwright (`qa/`), plus unit tests for pure systems if useful
- **Linting / formatting:** decided in phase 2
- **Asset / binary storage:** no Git LFS. Art is generated by code and baked to atlases.

## Project layout

Owner folders, as set by the brief (phase 2 writes the details into `docs/ARCHITECTURE.md`):

```
data/          game content JSON (units, enemies, bosses, spells, upgrades, levels, i18n)
src/contracts.ts  shared interfaces + event names (changes go through the lead agent)
src/systems/   economy (gold/iron/mana), progression, upgrades, waves, save
src/controls/  keyboard/mouse/touch input, spell buttons, aiming/targeting
src/render/    sprites, animation, spell FX, particles, camera, HUD
src/gameplay/  heroes, troops, enemies, bosses, spells, AI, data loading
qa/            Playwright tests
docs/          SPEC, ARCHITECTURE, STATE, BOSSES, ART_BIBLE, ADRs
reference/     notes on the original game (no original assets)
```

## Conventions

- **Simulation:** fixed 60 Hz timestep, with render interpolation. No speed, cooldown or timer is tied to frame count. Every data value is per second. (SPEC §8)
- **Communication:** a typed EventBus with `domain:action` names, declared in `src/contracts.ts`. Folders do not import each other's internals.
- **State:** one central game state. Systems mutate it through events or their own API, as defined in contracts.
- **Test hooks:** `window.render_game_to_text()` and `window.advanceTime(ms)`.
- **Code naming:** decided in phase 2.

## Out-of-scope dependencies

- No backend, Firebase, analytics or ads.
- No image-generation API keys. Art is vector drawn in code (phase-0 decision).
- No audio files from the original game or film.
